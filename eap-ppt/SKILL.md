# eap-ppt

## 从零开始创建 .pptx 文件

**阅读 [pptxgenjs.md](pptxgenjs.md) 了解详情。**

## 配色方案

| 角色 | HEX | 用途 |
| ----- | ----- | ----- |
| primary (dk1) | `ED6D34` | 品牌橙、主强调 |
| bg (lt1) | `FBFBFB` | 内容页近白底 |
| text (dk2) | `333333` | 正文 |
| secondary (lt2) | `F7A32A` | 金橙次要强调 |
| hyperlink | `FF0000` | 链接 |
| followed hyperlink | `3EBBF0` | 已访问链接 |

深色封面/结尾底可用 `333333`，其上正文用 `FFFFFF`。

## 字体

| 字体 | 用途 |
| ---- | ---- |
| OPPOSans B | 中文标题粗体 |
| OPPOSans H / L / M / R | 标题/细/中黑/正文 |
| 微软雅黑 | 中文后备 |
| Arial | 英文正文与标题搭配 |
| Barlow Medium | 英文可选 |

| 元素 | 中文 | 英文 |
| ---- | ---- | ---- |
| 页面标题 | OPPOSans B | Arial |
| 正文 | OPPOSans R | Arial |
| 页眉英文标签 / 页码 | OPPOSans M | Arial |

## 文本样式

| 元素 | 字号 | 字重 | 颜色 | 行距 | 对齐 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 页面标题 | 20pt | 粗体 | `333333` | 约 90% 或 1.5 倍行距 | 左 |
| 正文 L1 / L2 / L3 / L4+ | 28 / 24 / 20 / 18pt | 常规 | `333333` | 同上 | 左 |
| 幻灯片编号 | 10.5pt | 常规 | `D8D8D8` | — | 居中 |
| 页眉英文标签 | 9pt | 常规 | 约 75% 亮度灰 | — | 左，**全大写**（如 `ABOUT US`） |

封面级大标题可用约 36–44pt；段前 0、段后约 8–10pt。

## 版式类型

1. **封面**：全屏背景图、居中大标题、右下页码。  
2. **白色内容页**：底 `FBFBFB`；左上 Logo；左侧中文标题 + 英文标签；右上企业标识；右下页码；正文区左对齐。  
3. **图片网格**：白底；内容区 **3 列等宽图**；标题区在左。  
4. **空白背景**：整页背景图 + 页码，大块自定义内容。

## 固定元素（英寸，便于 PptxGenJS）

由 EMU÷914400 换算，可按需四舍五入到小数点后两位。

| 元素 | x | y | 宽×高（若适用） |
| ---- | --- | --- | ---------------- |
| Logo | 0.54 | 0.46 | 0.53 × 0.29 |
| 中文页面标题 | 1.03 | 0.42 | — |
| 英文页眉标签 | 2.20 | 0.40 | — |
| 企业标识（右上） | 11.28 | 0.50 | — |
| 幻灯片编号 | 12.83 | 7.10 | — |

**图片网格（量级）：** 单列宽约 **3.72 in**，列间距约 **0.22 in**（对应约 3400000 / 200000 EMU）。

**边距：** 内容区距幻灯片边缘至少 **0.5 in**；勿压住 Logo、企业标识、页码与标题区。

## 避免

- 不要用与本规范无关的配色当主色。  
- 不要将正文大面积居中（页码除外）。  
- 不要在标题下加「AI 味」装饰线；用留白或色块区分。  
- 低对比：浅底勿用浅灰正文；深底正文用白。  
- 列表用 PptxGenJS 的 `bullet: true`，勿手写 `•`。  
- 文本框与形状对齐时注意 `margin: 0`（见 pptxgenjs.md）。

## 质检（必做）

**默认有问题，你的任务是找出来。**

第一版渲染几乎不会完美。把质检当「找 bug」，不是走过场。若第一遍看不出任何问题，多半看得不够细。

### 内容质检

```bash
python -m markitdown output.pptx
```

检查缺内容、错别字、顺序错误。

**使用模板时，检查是否残留占位符：**

```bash
python -m markitdown output.pptx | grep -iE "xxxx|lorem|ipsum|this.*(page|slide).*layout"
```

若 grep 有输出，修完再宣告成功。

### 视觉质检

**⚠️ 使用子代理（Subagents）**——即便只有 2–3 页。你看代码久了会「脑补」预期画面。子代理视角更干净。

将幻灯片转为图片（见下文 [转为图片](#转为图片)），再用如下提示词：

```
请逐张检查这些幻灯片。默认存在问题，请找出来。

关注：
- 元素重叠（文字压在形状上、线穿过字、多层堆叠不当）
- 文字溢出或被边缘/文本框裁切
- 装饰线按单行标题设计，但标题折成两行导致错位
- 引用来源或页脚与上方内容相撞
- 间距过密（小于约 0.3"）或卡片/区块几乎贴在一起
- 留白不均（一处很空、另一处很挤）
- 距幻灯片边缘不足约 0.5"
- 多列或同类元素纵向/横向不对齐
- 对比度不足（如奶油底上的浅灰字）
- 图标对比度不足（如深色底上的深色图标且无反差色圆底）
- 文本框过窄导致过度折行
- 残留占位内容

每张幻灯片请列出问题或可改进点，即便较轻微。

请阅读并分析以下图片：
1. /path/to/slide-01.jpg（预期：[简要说明]）
2. /path/to/slide-02.jpg（预期：[简要说明]）

请报告所有发现的问题，包括轻微问题。
```

### 验证循环

1. 生成幻灯片 → 转图 → 检查
2. **列出发现的问题**（若声称没有，请更苛刻地再看一遍）
3. 修复
4. **对受影响的页重新验证**——一处修改常引出另一处问题
5. 重复直至整遍检查无新问题

**至少完成一轮「修复 → 再验证」后，才可宣告成功。**

## 转为图片

将演示转为单页图片以便目视检查：

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
pdftoppm -jpeg -r 150 output.pdf slide
```

会生成 `slide-01.jpg`、`slide-02.jpg` 等。

修复后只重渲某些页时：

```bash
pdftoppm -jpeg -r 150 -f N -l N output.pdf slide-fixed
```

## 依赖

- `pip install "markitdown[pptx]"` — 文本提取
- `pip install Pillow` — 缩略图网格
- `npm install -g pptxgenjs` — 从零生成
- LibreOffice（`soffice`）— 转 PDF（沙箱环境可通过 `scripts/office/soffice.py` 自动配置）
- Poppler（`pdftoppm`）— PDF 转图片
